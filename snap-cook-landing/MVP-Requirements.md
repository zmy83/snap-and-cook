## 一、产品概述

### 1.1 产品定位
拍食材 → 选菜系 → AI 生成食谱 → 跟着做

### 1.2 核心价值主张
让每个人都能用冰箱里的现有食材，做出世界各地的美食。

### 1.3 目标用户
- 海外家庭烹饪爱好者（25-45 岁）
- 不知道"今晚吃什么"的忙碌上班族
- 想尝试各国美食但不会搭配的新手
- 想减少食物浪费的环保主义者
- 有特殊饮食需求的人群（过敏、宗教、健康）

## 二、MVP 功能范围

### 2.1 核心功能（必须）

#### 功能 1: 食材识别
**输入**: 用户上传食材照片  
**处理**: 调用 Google Vision API 识别食材  
**输出**: 返回识别到的食材列表（可编辑）

**技术要求**:
- 支持常见食材 500+ 种
- 识别准确率 > 85%
- 响应时间 < 3 秒

#### 功能 2: 菜系选择
**输入**: 用户选择想要的菜系  
**选项**: 8 个首发菜系
- 🇨🇳 Chinese（中餐）
- 🇮🇳 Indian（印度菜）
- 🇹🇭 Thai（泰国菜）
- 🇮🇹 Italian（意大利菜）
- 🇲🇽 Mexican（墨西哥菜）
- 🇯🇵 Japanese（日本菜）
- 🇰🇷 Korean（韩国菜）
- 🇺🇸 American（美式）

**技术要求**:
- 单选或多选
- 支持"任意菜系"选项

#### 功能 3: 个性化设置
**输入**: 用户填写
- 用餐人数（1人 / 2人 / 3-4人 / 5+人）
- 饮食限制（多选）:
  - 素食 / 纯素 / 无麸质 / 无乳制品
  - 坚果过敏 / 海鲜过敏 / 鸡蛋过敏 / 大豆过敏
  - 清真 / 犹太洁食
  - 低钠 / 低糖
- 难度等级（简单 / 中等 / 挑战）

#### 功能 4: AI 食谱生成
**输入**: 
- 食材列表
- 菜系选择
- 用餐人数
- 饮食限制

**处理**: 调用 Claude/GPT-4 API 生成食谱

**输出**: 3-5 个食谱推荐，每个包含:
- 菜名（中英文）
- 难度星级
- 预计时间
- 调整后的食材用量
- 缺失食材提示
- 替代方案建议
- 详细步骤
- YouTube 教学视频链接

**技术要求**:
- 生成时间 < 10 秒
- 食谱必须适配用户的饮食限制
- 自动调整食材分量

#### 功能 5: 食谱详情页
**展示内容**:
- 完整食材清单（✅ 已有 / ❌ 缺失）
- 分步骤说明（带序号）
- 营养信息（可选）
- YouTube 视频嵌入
- 购物清单导出

## 三、技术架构

### 3.1 前端
**技术栈**: React + Next.js  
**UI 框架**: Tailwind CSS  
**部署**: Vercel

**页面结构**:
```
/                    # 首页（Landing Page）
/app                 # 主应用入口
/app/upload          # 上传食材照片
/app/customize       # 选择菜系 + 个性化设置
/app/recipes         # 食谱列表
/app/recipe/[id]     # 食谱详情
```

### 3.2 后端
**技术栈**: Node.js + Express  
**数据库**: Firebase Firestore（NoSQL）  
**部署**: Firebase Functions

**API 端点**:
```
POST /api/identify-ingredients    # 识别食材
POST /api/generate-recipes        # 生成食谱
GET  /api/recipe/:id              # 获取食谱详情
POST /api/export-shopping-list    # 导出购物清单
```

### 3.3 第三方服务

| 服务 | 用途 | 成本估算 |
|------|------|----------|
| Google Vision API | 图像识别 | $1.50 / 1000 次 |
| Claude API / GPT-4 | 食谱生成 | ~$0.01 / 次 |
| YouTube Data API | 视频搜索 | 免费 |
| Firebase | 后端 + 数据库 | 免费 → $25/月 |

## 五、用户流程

### 5.1 主流程
```
1. 用户访问首页
   ↓
2. 点击 "Get Started"
   ↓
3. 上传食材照片
   ↓
4. AI 识别食材（用户可编辑）
   ↓
5. 选择菜系
   ↓
6. 填写用餐人数 + 饮食限制
   ↓
7. AI 生成 3-5 个食谱
   ↓
8. 用户选择一个食谱
   ↓
9. 查看详细步骤 + 视频
   ↓
10. 开始烹饪！
```

### 5.2 异常处理
- 照片识别失败 → 提示手动输入食材
- 无法生成食谱 → 建议调整菜系或食材
- 视频链接失效 → 显示文字步骤

## 六、UI/UX 要求

### 6.1 设计原则
- **简洁**: 每页只做一件事
- **快速**: 3 次点击内完成核心流程
- **友好**: 清晰的错误提示和引导
- **响应式**: 完美支持手机端

### 6.2 关键页面设计

#### 上传页面
- 大按钮："拍照" / "从相册选择"
- 预览已上传的照片
- 识别进度条

#### 食谱列表页
- 卡片式布局
- 显示：菜名、难度、时间、缺失食材数
- 快速筛选按钮

#### 食谱详情页
- 顶部：大图 + 菜名
- 中部：食材清单（分已有/缺失）
- 底部：步骤 + 视频

## 九、风险与应对

| 风险 | 影响 | 应对方案 |
|------|------|----------|
| AI 成本过高 | 高 | 限制免费用户次数 |
| 识别准确率低 | 中 | 允许手动编辑 |
| 视频链接失效 | 低 | 提供文字步骤 |
